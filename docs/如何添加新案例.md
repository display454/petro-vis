# 如何添加新案例

这份文档是站内「接入指南」（`#/guide`）的离线版，内容一致，适合离线阅读或发给协作者。

## 两条路

| | 方式 A · 上传案例包 | 方式 B · 写插件 |
|---|---|---|
| 门槛 | 不写代码（示范页会 HTML/CSS/JS 即可） | 会一点 JS |
| 内容 | 专业背景 + 案例流程 + 完整示范 | 三块内容全可定制 |
| 可运行示范 | 自带：整页 HTML / demo.js 均可 | 可以放真实算法 |
| 保存位置 | 本机浏览器（localStorage） | 磁盘文件，永久 |
| 入口 | 导航「＋ 添加案例」 | 本文三步接入 |

## 方式 A：上传案例包（推荐先试这个）

### 案例包长什么样

一个**文件夹**，最少只有一份清单，其余随便：

```
my-case/
  case.json          清单（必需）：元信息 + 专业背景 + 案例流程
  demo/index.html    示范页（可选，整页模式）
  demo/demo.css      示范页样式（可选）
  demo/demo.js       示范脚本（可选；没有 html 时它就是模块模式的挂载脚本）
  *.png / *.svg / *.json…   任意素材，放进来即可被引用
```

### 怎么接入

1. 在「添加案例」弹窗里点 **下载案例包模板（.zip）**——解压就是一个能直接跑的完整包
   （清单 + 示范页 + 样式 + 脚本），也可以只用 `assets/cases/_template.case.json` 这份清单模板；
2. 改清单里的 `id`（小写字母/数字/连字符，全站唯一）、`sceneId`（绑定哪个场景，等于选定分类）、
   `title`，以及两块正文——`tabs.background`（导语 + 30 秒判断 + 四段式 `sections[]`）和
   `tabs.workflow`（步骤 `steps[]`、指标 `metrics`、失败模式 `fails[]`）；
3. 把 `my-case` **整个文件夹**拖回弹窗（推荐方式，支持多级子目录）。如果浏览器不支持
   「选择文件夹」按钮（点了弹出的仍是文件选择框，常见于国产浏览器兼容模式），三个替代办法：
   直接把文件夹拖进虚线框 / 点「选择文件」后 Ctrl+A 全选包内所有文件 / 改用 Chrome 或 Edge。
   多选文件时清单、示范页仍能按文件名自动对上（支持文件夹、多选文件、逐个添加），
   右侧会**逐项显示校验结果**——红色必须改，黄色可以忽略；点「▶ 试跑示范」可以在沙箱里先看效果；
4. 全绿后点 **校验并添加**：案例立即注册并写入本机浏览器，自动跳到对应场景页，三个 tab 当场出现。

### 示范的两种写法

**A. 整页模式** —— 包里有 `demo/index.html`：

- 整页运行在 **sandbox iframe** 里，样式脚本完全隔离，图表、Canvas、第三方库随便用；
- `<link href="demo.css">` 与 `<script src="demo.js">` 会被自动内联，
  图片等素材的相对路径会被自动替换成内嵌资源——**不需要服务器，双击 index.html 也能跑**；
- 脚本里可以用 `window.caseAsset("core.png")` 取素材地址。

**B. 模块模式** —— 只有 `demo/demo.js`（没有 html）：

- 脚本被执行，挂进 **Shadow DOM**，上传的 CSS 也注入 Shadow DOM，不会污染主站；
  样式里可以直接用站点令牌 `var(--jade)` 等；
- 需要导出挂载函数，三种写法任选：

```js
module.exports = {
  mount: function (root, api) { /* root 是你的容器 */ },
  unmount: function () { /* 清定时器、事件监听 */ }
};
// 或 exports.mount = function (root, api) {...}
// 或 window.__CASE_MOUNT__ = function (root, api) {...}
```

- `api` 对象：`api.asset(name)` 取素材地址、`api.readText(name)` 读文本素材、
  `api.list()` 列包内文件、`api.scene` / `api.kase` 拿场景与案例元数据、`api.onDestroy(fn)` 注册清理。

两者都没有时，也可以在清单里写 `tabs.demo.builtin = "welllog-layer"` 复用已有示范。

### 注意

- 上传的案例保存在本机浏览器里：刷新、关页面都在；换电脑或换浏览器需要重新上传；
  案例库列表里带「本地导入」标记，可一键移除。要永久发布给所有人，走方式 B。
- 单包上限 6 MB（超过会拦截，1.5 MB 以上会提醒）；图片先压缩，视频请放外部链接。
- 同一场景上传新案例后，场景页会**优先展示上传的这份**（后传的覆盖先传的），旧案例仍留在案例库里。

## 系统的三层结构

```
┌─ 03 外壳层  assets/core/*      路由 / 导航 / 组件 / 设计令牌，一般不用动
├─ 02 案例层  assets/cases/*     每个案例一个文件，即插即用 ← 你要改的只有这里
└─ 01 数据层  assets/data.js     13 环节 / 61 场景的元数据
```

新增一个案例，**只动第 2 层的一个文件**，外加 `index.html` 里一行 `<script>`。

## 三步接入

### 第 1 步：复制模板，改三处

把 `assets/cases/_template.case.js` 复制成 `<你的案例id>.case.js`，只改三处：

| 要改的 | 说明 |
|---|---|
| `id` | 全局唯一，kebab-case，例如 `d3-mudloss` |
| `sceneId` | 必须是 `data.js` 里已有的场景 id（如 `w1`）。场景不存在时先去 `data.js` 对应环节的 `scenes` 数组里加一条元数据 |
| `tabs` 里的内容 | 三个 tab：background / workflow / demo（demo 可选） |

### 第 2 步：在 index.html 里挂上去

```html
<script src="assets/cases/welllog-layer.case.js"></script>
<script src="assets/cases/welllog-layer.demo.js"></script>
<script src="assets/cases/你的案例.case.js"></script>   <!-- ← 加在这里 -->

<script src="assets/core/shell.js"></script>            <!-- 必须在 shell.js 之前 -->
```

加载顺序：`data.js → registry.js → kit.js → 案例 → shell.js`。
案例必须在 `shell.js` **之前**注册完，否则首屏渲染时找不到它。

### 第 3 步：打开控制台看校验

刷新页面，进 **案例库**（`#/cases`）。系统自动检查：

- id 是否规范（kebab-case）
- `sceneId` 是否存在于 data.js
- background 是否至少 2 段、每段有无 title 和内容
- workflow.steps 是否非空
- `tabs.demo.mount` 是否为函数
- 场景的 `demo:true` 标记与案例是否一致
- 同一场景是否被多个案例绑定

全绿即接入完成：场景页的 tab、面包屑、相关场景、方法反查页的条目都会自动出现，**不需要改任何其他文件**。

## 契约字段

| 字段 | 级别 | 说明 |
|---|---|---|
| `case.json`（文件） | 必填 | 清单，放包根目录，建议就叫这个名字 |
| `demo/index.html`（文件） | 可选 | 整页示范，自动内联 css/js 与素材 |
| `demo/demo.js`（文件） | 可选 | 示范脚本；无 html 时为模块模式，需导出 mount |
| `demo/demo.css`（文件） | 可选 | 示范样式（整页模式进 iframe，模块模式进 Shadow DOM） |
| `id` | 必填 | kebab-case，全局唯一 |
| `sceneId` | 必填 | 绑定到 data.js 的场景 id |
| `methods` | 可选 | 数组。案例涉及的 AI 技术（如 `["ts","cv"]`），也可在导入弹窗里勾选；不填则继承场景标签。 |
| `title` | 必填 | 案例标题 |
| `status` | 建议 | `ready` 可用于教学；`draft` 未定稿（控制台标黄） |
| `version` / `updated` | 建议 | 语义化版本 / 最后更新日期 |
| `tabs.background` | 必填 | `judge`（30 秒判断）+ `lede`（导语）+ `sections[]`（四段式） |
| `tabs.background.sections[]` | 必填 | 每段 `{ no, en, title, html }`，建议恰好四段 |
| `tabs.workflow` | 建议 | `title` / `lead[]` / `stats[]` / `steps[]` / `metrics` / `fails[]` |
| `tabs.workflow.steps[]` | 建议 | 每步 `{ name, do, role, effect, trap }` |
| `tabs.demo` | 可选 | `{ mode, html, js, label, intro, height }` 或 `{ builtin }` |
| `tabs.demo.mode` | 可选 | `auto`（默认，自动判断）/ `page` / `module` / `builtin` |
| `tabs.demo`（插件写法） | 可选 | `{ label, mount(root, ctx), unmount() }` |

## 工具箱（不要在案例里写 CSS 类名）

| 函数 | 用途 |
|---|---|
| `K.sec4(no, en, title, html)` | 四段式中的一段 |
| `K.figure(svg, no, caption)` | 插图 + 图注 |
| `K.judge([{label,value,desc,html}])` | 顶部"30 秒判断"格子 |
| `K.checklist(items)` | 可勾选的数据清单，items 为 `[名称, 规格, 标注要求]` |
| `K.dtable(head, rows)` | 数据表格 |
| `K.pipeline(steps)` | 编号流程步骤 |
| `K.fails([{name, why}])` | 失败模式宫格 |
| `K.cells([[标签, 值]])` | 指标格（纯数字自动放大） |
| `K.meter(diff)` | 三段难度条，diff ∈ 低/中/高 |
| `K.refs([...], href)` | 参考方向胶囊 |
| `K.callout(text, 'warn')` | 提示条 |
| `K.code(str, {file})` | 代码块（带语法着色） |

文本里可直接用 `**粗体**` 与 `` `等宽` `` 两种标记；所有函数自动转义 HTML。

## 颜色规范

浅色主题。案例内写颜色时只用两类值：

1. 设计令牌：`var(--jade)` 主色、`var(--clay)` 强调、`var(--c-cv)` 等方法色、`var(--ink-2)` 等文字色；
2. 直接写低饱和的浅色 hex（如 `#e6f1ec`、`#b26a39`）。

**不要写深色背景**。全站唯一的深色元素是代码块（`.code`）。

## 四个常踩的坑

1. **script 顺序放反** —— 案例写在 shell.js 后面，页面渲染完了才注册，控制台里能看到但场景页没有 tab。
2. **sceneId 拼错** —— 不报 JS 错误，案例只是永远不出现。案例库的"绑定场景"列会显示 ⚠。
3. **demo 里没有清理** —— 用了 `setInterval` / `window` 级事件监听，要在 `unmount()` 里清掉。
4. **把样式写死在案例里** —— 内联深色会让案例在改配色时掉队；颜色一律用令牌或 `K.*`。

## 删除一个案例

删掉 `assets/cases/<id>.case.js`（和可选的 `.demo.js`）以及 index.html 里对应的 `<script>` 行即可。场景自动回到"待接入"状态，系统其他部分不受影响。

## 删除案例

案例库（`#/cases`）表格里每个案例都有删除入口，行为按案例来源区分：

| | 上传的案例（带「本地导入」徽标） | 插件案例（.case.js） |
|---|---|---|
| 点击后 | 清掉浏览器里保存的案例包存档 | 记入隐藏名单，站点立即不再显示 |
| 磁盘文件 | 不受影响 | 保留在 `assets/cases/`，不动 |
| 刷新后 | 不再出现（存档已清） | 保持隐藏 |
| 恢复 | 重新上传即可 | 案例库「已删除的插件案例」区点「恢复」，刷新后回来 |

删除是即时生效的：确认对话框点「确定」后页面就地更新，不需要手动刷新。
程序化接口：`CaseImport.remove(id)` 删除，`CaseImport.restore(id)` 恢复插件案例。
